## Search evidence and honesty

The flagged conversation shell adds a location-scoped search panel. `all` displays a location-selection message without making a request. Its server endpoints reject `all`, validate accepted workspace membership and manager location scope, and resolve the website/market from the selected location’s server record. Owners explicitly request new reads; listing saved reads never calls a provider. No private thread notes, document text or client-provided site/market/source/brief enter the request.

Stage 3 extends the **same Stage 2 GSC readonly adapter**. The existing connection must have a matching verified property. The bounded query remains at most 25 reported queries over 28 finalized days ending three Pacific calendar days before the request, with the existing timeout/body limits. The date anchor follows `America/Los_Angeles`, including daylight-saving changes. Stage 3 additionally pins `web`, a country filter (`hkg` / `twn`) and an anchored page regex for the selected website origin/path. A parent domain property therefore cannot silently supply a sibling site’s queries. With a page filter Google requires page aggregation; the request explicitly uses `byPage`. Its date window, Pacific timezone, country, site filter, aggregation, source property and read timestamp are retained. A second bounded query (at most 28 date rows, inside the same timeout) checks that every day of the requested window has reported data. Missing/malformed/failed date history keeps the query evidence partial and ineligible for comparison. Stage 2’s standalone worldwide context behavior is preserved.

The review heuristic selects at most five likely Chinese-language queries with at least 20 impressions and zero clicks. It requires Han text and excludes explicit Japanese Kana and Korean Hangul; Han-only text can still be ambiguous, so this is not definitive language identification. The threshold is a conservative product heuristic, not statistical significance or proof of a content gap. The panel says the actual pages have **not** been checked, and asks the owner to review page answers/titles and confirmed shop facts. It does not infer missing pages, rankings, customer intent, local wins or LLM visibility. English-only evidence, thin samples, unsupported/unscoped evidence and failed/disconnected reads keep honest partial/empty/unavailable/failed states. Mixed-language and bounded/malformed samples remain partial. Missing query data never becomes zero.

Paid enrichment is optional in the brief and is deliberately not part of the Stage 3 inference path. Stage 2 Firecrawl/DataForSEO controls, exact flags, market allowlist, account reservations, budgets, timeouts, failure handling and pricing gates are reused unchanged on their existing surface. Their English SERPs/site text are not relabeled as HK gap evidence or comparable baselines. Stage 3 never triggers a paid call.

The request contract follows the official [Search Analytics query reference](https://developers.google.com/webmaster-tools/v1/searchanalytics/query): country filtering, page filtering/aggregation, finalized data, Pacific dates and top-row limitations. This is documentation verification, not live GSC acceptance.

## Draft, confirmation and task

A deterministic shop-language brief is saved alongside each usable gap in en, zh-HK and zh-TW. It states what was observed, what remains unverified, why to review it and the next shop actions, with the actual website/property/country/window/read-time citation. The selected queries and original metrics remain in the pinned gap. Missing evidence produces no brief. There is no new model, generation/AI usage write, document substitution or second Ask Kinnso path.

“Review brief” reveals the saved draft. The owner must read it and check an explicit confirmation before “Confirm brief and add task” is available. The API requires `confirmed: true` and owner membership again. A transaction locks the saved record, rechecks accepted ownership, creates an existing-style `owner_objective` / `website-basics` todo through `actionMutationRepository`, pins its ID/confirmation time and writes the normal `action.updated` audit. Failure rolls back all three writes. The todo keeps the confirmed brief, query list and source in its existing localized summary/evidence. It requires the usual confirmed input before its text workflow can run. No model runs automatically.

The new snapshot is the immutable approved **brief**, not an approved publishable output. The task’s later output versions still require the existing version confirmation and copy/export flow. Confirmation, draft creation, gap reads and observation do not write output versions, deliveries or delivery usage. Existing permissions and scoring rules are unchanged.

Repeated confirmation returns the same todo even after completion. Re-reading identical final evidence reuses the original saved brief rather than offering another confirmable copy; the UI separately shows the most recent check time. Changed evidence appends another snapshot. The original citation/read time and approved brief cannot be rewritten by copy changes, later chat or refresh. Linking a shared task never copies or shares private thread notes.

## Observe

Only an approved brief can request an observation. This uses the same read-only GSC adapter against the current selected location; there is no polling, auto-sync, write or publish. The approved brief and original task stay visible beside the later evidence.

Comparison requires an original usable, non-partial baseline and later non-partial GSC source, the exact same website/property/market/country/page filter/search type/query dimension/aggregation/final-data state/row limit, equal 28-day windows with all 28 days actually reported in each, no overlap, and a later window beginning after the entire Pacific date of confirmation. Every approved query must be present in the later sample with at least 20 impressions. Missing or suppressed queries do not become zero. Bounded/changed/failed coverage, insufficient history or a missing baseline produces a specific honest empty/partial message.

A valid comparison displays only the exact queries’ observed clicks/impressions in the two windows, with both windows and source timestamps. It calculates no percentage lift, whole-site totals, rankings or causal attribution. Because the latest query window lags by three days, a usable post-confirmation window normally requires at least a month. A change in counts does not establish that the approved task was implemented or caused it.

## Minimal schema and Preview steps

Migration `0020_conversation_search.sql` adds **one table** for bounded immutable gap/brief snapshots, an evidence fingerprint and a one-time owner confirmation/task reference. This durable source snapshot is necessary for honest later comparisons; browser-local notes cannot provide an authoritative baseline or atomic idempotent confirmation. Existing action, output-version, delivery, scoring and membership schemas are unchanged. The trigger fixes source/draft content even before confirmation, permits only the first valid owner confirmation, and allows only actor erasure/workspace deletion lifecycle exceptions. Location IDs are historical snapshots: deleting a location never moves a brief into `all`. Runtime may append/read and update only confirmation columns. There is no new thread store or ACL redesign.

1. Use the normal reviewed migration process to apply 0019 and 0020 to an explicitly authorized Preview database. This PR does not apply shared/hosted migrations.
2. Set only the chosen Preview’s server `CONVERSATION_HOME_ENABLED=true`, with `VERCEL_ENV=preview`. Production remains OFF/unset. Existing Stage 1 gate semantics force `VERCEL_ENV=production` off even if the flag is true.
3. Reuse `GOOGLE_OAUTH_CLIENT_ID`, `GOOGLE_OAUTH_CLIENT_SECRET`, `GOOGLE_OAUTH_REDIRECT_URI`, `OAUTH_TOKEN_ENCRYPTION_KEY` and the Stage 2 readonly GSC connection. No Stage 3 environment keys are added. Paid provider keys/flags, including `DATAFORSEO_MARKETS`, stay optional/default OFF under Stage 2 rules.
4. From Today choose Start work, select one location, connect its verified Search Console property, then Read search gaps → Review brief → explicitly confirm → open the task or observe later signals. Refresh/list old snapshots to check that the approved text stays fixed. Try `all`, an unsupported/disconnected source, English-only/thin evidence and an immediate observe to see honest empty/partial states.
