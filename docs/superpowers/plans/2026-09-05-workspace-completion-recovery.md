# Workspace completion recovery — bounded design and rollout dependency

Date: 2026-09-05. Status: local helper-recovery slice implemented; durable cross-runtime completion is NOT complete. This document is a proposed follow-up contract, not evidence of deployed behavior or permission to modify shared services.

## Reproduction and implemented boundary

Fixture tests in `lib/workspace/post-process.test.ts` reproduced five failures before the fix: measurement exceptions returned success and still announced completion; notification insert failures returned by the best-effort helper were ignored for done, partial, and failed jobs; action derivation failure discarded the already-persisted snapshot ID. The local fix returns these errors, retains snapshot ID, and withholds completion notification until required earlier steps succeed. Job lookup errors also remain visible. Public/unclaimed and nonterminal jobs still create no workspace side effects. Calling the hook again reads the terminal result; it does not call scan collectors or rewrite audit_jobs.

This is outcome/log visibility only. `runScan` still returns the original scan result. The helper slice itself supplies no persisted retry ledger, process-exit recovery worker, or exactly-once cross-runtime guarantee. Notifications now deduplicate using a deterministic UUIDv8 primary key for workspace/job/kind/recipient and ignore conflicts without resetting read state. Current fixture tests mock side-effect helpers and prove orchestration/error propagation, not SQL transactionality, runner parity, recipient deduplication, or recovery after each database write.

Source inspection also found issues requiring the follow-up transaction design: snapshot creation and its audit insert are separate, with audit errors swallowed; action audit uses check-then-insert and ignores insert errors; measurement insertion and action measurement_state updates are separate and update failures only log. A retry skips existing measurements and cannot repair that missed state update. Snapshot rebuilding may rerun website checks. The local slice now repairs snapshot audits with stable idempotency keys, reuses saved snapshot evidence, propagates action audit errors with idempotent inserts, and repairs action measurement state from existing persisted measurement rows. Measurement inserts use deterministic per-action/head-snapshot UUIDs. A comparable scan with missing measurement base remains retryable rather than announcing completion. Sequential older-snapshot retries skip action refresh/closure once a newer same-location snapshot exists. These protections do not fence stale concurrent workers.

## Proposed authoritative completion owner

Keep the existing Cloudflare scheduler and legacy queued runner as the execution owner; add a bounded reconciliation phase to that existing tick. No second cron and no browser-only retry. Successor owns workspace outcome computation and its service-authenticated completion endpoint. Legacy retains report/email/digest ownership. Workspace reconciliation never calls collectors or dispatches a scan.

Proposed endpoint `POST /api/internal/workspace-scan-completion` accepts only UUID `jobId`. It uses a dedicated server-only `WORKSPACE_COMPLETION_SECRET` with exact Bearer authentication and timing-safe comparison; enforce a minimum 32-byte randomly generated value, fail closed if absent, reject browser/session credentials and ignore supplied workspace/location/status. Resolve job linkage and terminal state using a service-role database client. Origin configuration `WORKSPACE_COMPLETION_ORIGIN` must be HTTPS bare origin (localhost permitted only in isolated tests); disable redirects so the credential cannot be forwarded. Do not reuse a public scan session token or expose a service role key to callers.

The legacy inline completion and legacy `/api/scan/notify` callback must request this endpoint after terminal persistence, independently of legacy email outcomes. A completion failure must not rerun collectors or rewrite a valid scan status. Return a separate completion error/503 for retry scheduling, not a claim that the scan failed. Public/unclaimed jobs return skipped and create no workspace rows. The existing five-minute tick also discovers terminal workspace jobs without completed ledger entries, including jobs missed before ledger creation, so a process exit before the first callback is recoverable. Bound reconciliation batch size/time before selecting one ordinary runnable scan; failure of reconciliation must not starve unrelated scans.
